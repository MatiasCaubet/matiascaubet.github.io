01 / Approach

Predictable first, flexible second.

i.

Deterministic first

If a rule, a query or an index solves the case, there is no need for a model. It is cheaper, faster and explainable.

ii.

The model proposes, the rules validate

When a model is involved, its output is checked against a closed set of valid answers. Whatever fails the check does not go out.

iii.

Traceable, with a fallback

Every result says which layer produced it. If the AI component fails, the service keeps answering with what it can still guarantee.

01 Academic project
Healthcare

Searching symptoms written in everyday language

Matching colloquial Spanish to clinical terms, without inventing symptoms.

exact→prefix→trigrams→embeddings→validation

Problem

Clinicians type symptoms the way patients say them, and standard clinical terminology does not always use those words.

Approach

  • Exact and prefix search
  • Trigram similarity in PostgreSQL
  • Embeddings only when lexical search falls short
  • Every suggestion is filtered against the catalogue of valid symptoms

Result

Quantized model from 118 to 35 MB and latency from 5–8 s to ~0.5 s. The tool suggests; the clinician decides.

02 Research
NLP

Impersonal sentence classifier

A classifier that knows how to say “I don't know”.

rules→ambiguous?→model (next stage)

Problem

Detecting impersonal sentences in English text, a useful signal when reviewing the quality of technical writing.

Approach

  • Rules over the dependency tree
  • Small lexicons for frequent cases
  • Ambiguity is an explicit result: no label is forced

Result

A lightweight microservice that runs on CPU and reports which rule produced each result. Routing ambiguous cases to a model is designed as the next stage.
